# Lab 10 시나리오 · 1차·2차·3차 + 먼저 간 시간 + 술 + 먹은 양

Worker 정의: `docs/lab10/split_worker_definitions.yaml` (Supervisor 1 + Worker 5)
기대 금액은 아래 "나누는 규칙"으로 Python 계산기를 돌려 검산한 값입니다.

## 흐름

```text
split_supervisor
 ① receipt_agent          (mcp · get_receipt)            차수 시간·메뉴·금액·결제자
      └ 합계 불일치 → 중단, 사람 확인
 ② attendance_agent       (llm · openai)                  사람별 도착·떠난 시각, 술, 먹은 양
      └ 시각 없음·시간 밖·멤버 아님 → 중단, 확인 질문
 ③ menu_classifier_agent  (llm · gemini)                  메뉴 → food / alcohol / equal / personal
 ④ settlement_agent       (mcp · calculate_fair_split)    시간 비율 반영 계산, 송금 상계
 ⑤ explainer_agent        (llm · openai · 선택)           사람별 설명 (실패해도 완료)
 → SettlementPlan 통합
```

## 나누는 규칙

차수마다 **머문 시간 비율**을 먼저 구합니다.

```text
머문 시간 비율 = (그 차수에서 머문 분) ÷ (그 차수 전체 분)
예) 1차 18:00~20:00(120분)에서 19:30에 먼저 감 → 90 ÷ 120 = 0.75
```

| 메뉴 종류 | 가중치 | 누가 나누나 |
| --- | --- | --- |
| food (음식) | 머문 시간 비율 × 먹은 양 (적게 0.5 · 보통 1 · 많이 1.5) | 그 차수 참석자 |
| alcohol (술) | 머문 시간 비율 | 그 차수에서 **술 마신 사람만** |
| equal (자리값·노래방·공용 음료) | 머문 시간 비율 | 그 차수 참석자 |
| personal (개인 메뉴) | - | 주인 혼자 |

- 차수에 없던 사람은 비율 0이라 그 차수 금액이 0원입니다.
- 받을 돈은 100원 단위로 올립니다. 결제자 본인 몫은 올리지 않습니다. 남는 돈은 결제자 몫입니다.
- 차수마다 결제자가 달라도 서로 주고받을 돈은 상계해서 한 줄로 만듭니다.

검산 예시 (1차 음식 102,000원)

```text
가중치 = 머문 시간 비율 × 먹은 양
민수 1×1 = 1 · 지영 1×0.5 = 0.5 · 서준 0.75×1.5 = 1.125 · 하은 1×0.5 = 0.5
도윤 1×1.5 = 1.5 · 채원 0.75×1 = 0.75                       합계 5.375
가중치 1당 102,000 ÷ 5.375 = 18,977원
서준 = 1.125 × 18,977 + 콜라 2,000 = 23,349 → 23,400원 (100원 올림)
```

1차 술 50,000원은 마신 사람의 시간 비율(민수 1, 지영 1, 도윤 1, 채원 0.75 · 합 3.75)로 나눕니다. 채원은 50,000 × 0.75 ÷ 3.75 = 10,000원입니다.

## 발표 순서 제안

1. S1 → S2 → S3 → S4 → S5 순서로 **조건을 하나씩 켜며** 같은 영수증의 금액이 바뀌는 것을 보여 줍니다.
2. S6 종합 결과를 단순 N빵(46,167원)과 나란히 보여 줍니다. 가장 적게 내는 하은(15,200원)과 가장 많이 내는 도윤(81,300원)의 이유를 explainer_agent 설명으로 확인합니다.
3. E1(시각 없음)과 E6(영수증 합계 불일치)으로 "추측하지 않는다"를 보여 줍니다.

## 현재 Lab 10 코드와의 차이

현재 `split_flow.py`는 **차수 단위 참석**(참석/불참)만 지원합니다. 이 문서의 시간 비율 규칙을 쓰려면 다음이 필요합니다.

- `get_receipt` Mock 데이터에 차수별 `start`·`end` 시각 추가 (GATHER-1231)
- `attendance_agent` 출력 계약에 차수별 `arrived_at`·`left_at` 추가
- 계산을 `calculate_fair_split` MCP Tool로 옮기고 시간 비율 가중치 반영
- Guard: 시각이 차수 시간 안에 있는지, 도착 < 떠남인지 검사
